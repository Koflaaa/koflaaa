Dynamische :pseudoklassen
zum Anfassen

Dynamische Pseudoklassen selektieren Elemente nicht nach ihrer Position im Dokument, sondern nach ihrem aktuellen Zustand – z. B. „wird gerade berührt“, „hat den Fokus“ oder „enthält einen ungültigen Wert“. Jede Karte auf dieser Seite besitzt oben rechts eine Zustands-LED, die ausschließlich über die jeweilige Pseudoklasse geschaltet wird. Probieren Sie alles direkt aus.

Diese Seite verwendet kein JavaScript – alle Reaktionen sind reines CSS.

Link-Zustände :link · :visited · :any-link · :target

Zustand

:link & :visited

Unterscheidet unbesuchte von bereits besuchten Links. Besuchte Links erscheinen hier violett – abhängig von Ihrem Browser-Verlauf.

MDN Web Docs (vermutlich besucht) Ein sehr wahrscheinlich unbesuchter Link 
a:link    { color: blau; }
a:visited { color: violett; }
Zustand

:any-link

Fasst :link und :visited zusammen: trifft auf jedes Element mit href zu – egal ob besucht oder nicht. Die LED ist deshalb dauerhaft an.

Link mit href → selektiert Anker ohne href → nicht selektiert 
a:any-link { text-decoration-thickness: 2px; }
Zustand

:target

Trifft auf das Element zu, dessen id gerade als Fragment in der URL steht (#kapitel-2). Klicken Sie einen Sprunglink:

→ Kapitel 1   → Kapitel 2

#kapitel-1
#kapitel-2
:target { background: hervorgehoben; }

Interaktion :hover · :active · :focus · :focus-visible · :focus-within

Zustand

:hover

Aktiv, solange der Mauszeiger über dem Element steht. Auf Touch-Geräten gibt es diesen Zustand nicht wirklich (siehe Grenzen unten).

Maus hierher bewegen
.feld:hover { background: akzent; }
Zustand

:active

Aktiv nur während des Drückens (zwischen mousedown und mouseup). Halten Sie die Maustaste gedrückt, um den Zustand zu „verlängern“.

button:active { transform: translateY(1px); }
Zustand

:focus

Aktiv, solange das Element den Tastatur-/Eingabefokus besitzt – egal ob per Klick oder per Tab erreicht.

input:focus { border-color: akzent; }
Zustand

:focus-visible

Wie :focus, aber nur wenn der Browser einen sichtbaren Fokusring für sinnvoll hält – typischerweise bei Tastaturbedienung. Vergleichen Sie: Button anklicken vs. per Tab anspringen.

button:focus-visible { outline: 3px solid akzent; }
Zustand

:focus-within

Trifft auf ein Element zu, sobald irgendein Nachfahre den Fokus hat. Ideal, um ganze Formulargruppen hervorzuheben.

.gruppe:focus-within { border-color: akzent; }

Formular-Zustände :checked · :enabled · :disabled · :placeholder-shown

Zustand

:checked

Aktiv bei angehakten Checkboxen, gewählten Radiobuttons und ausgewählten <option>-Elementen. In Kombination mit Geschwister-Selektoren die Basis vieler CSS-only-Schalter.

→ Status wird per CSS angezeigt 
input:checked ~ .antwort { color: grün; }
Zustand

:enabled & :disabled

Unterscheidet bedienbare von gesperrten Formularelementen. Gesperrte Felder erhalten hier automatisch eine gestrichelte Optik.

input:enabled  { border-color: grün; }
input:disabled { background: grau; }
Zustand

:placeholder-shown

Aktiv, solange ein Eingabefeld leer ist und deshalb seinen Platzhaltertext anzeigt. Tippen Sie etwas – die Markierung verschwindet.

input:placeholder-shown { border-color: gelb; }

Validierung :valid · :invalid · :in-range · :out-of-range

Zustand

:valid & :invalid

Reagiert live auf die HTML5-Formularvalidierung (type, required, pattern …). Geben Sie eine gültige E-Mail-Adresse ein:

input:valid   { border-color: grün; }
input:invalid { border-color: rot; }
Zustand

:in-range & :out-of-range

Für Zahlenfelder mit min/max. Erlaubt sind hier Werte von 1 bis 10 – probieren Sie z. B. 42.

input:in-range     { border-color: grün; }
input:out-of-range { border-color: rot; }

Grenzen & Praxisprobleme

:hover – existiert auf Touch-Geräten nicht wirklich

Es gibt keinen Mauszeiger, der „über“ einem Element schweben kann. Mobile Browser simulieren :hover beim Antippen, was zum „Sticky-Hover“-Problem führt: Der Zustand bleibt nach dem Tippen hängen, bis woanders getippt wird. Wichtige Inhalte oder Funktionen dürfen daher nie ausschließlich über :hover erreichbar sein – Tastatur- und Touch-Nutzer würden ausgeschlossen. Abhilfe: @media (hover: hover) und Fokus-Stile als Ergänzung.

:visited – aus Datenschutzgründen stark beschnitten

Früher konnte man über :visited den Browser-Verlauf fremder Nutzer ausspähen („History Sniffing“): Eine Seite legte tausende unsichtbare Links an und las per Skript aus, welche davon „besucht“ gestylt wurden. Browser erlauben für :visited deshalb heute nur noch wenige Farb-Eigenschaften (u. a. color, background-color) – keine Größen, Bilder oder Positionen – und Skripte erhalten beim Auslesen bewusst die Werte des unbesuchten Zustands. Viele kreative :visited-Ideen funktionieren deshalb schlicht nicht.

:focus vs. :focus-visible

Ein Fokusring bei jedem Mausklick wirkt für viele störend, weshalb er früher oft per outline: none entfernt wurde – eine Katastrophe für Tastaturnutzer. :focus-visible löst den Konflikt: Der Ring erscheint nur, wenn er gebraucht wird. Die Entscheidung trifft allerdings die Heuristik des Browsers, nicht der Autor.

:target – nur ein Fragment pro Seite

Es kann immer nur ein Element gleichzeitig :target sein, der Zustand hängt an der URL und geht bei Navigation verloren. Für CSS-only-Tabs oder -Overlays ist :target deshalb eher ein Trick als eine robuste Lösung – u. a. weil jeder Klick einen Verlaufseintrag erzeugt und die Seite zum Ziel scrollt.

:invalid – Timing als UX-Problem

:invalid greift sofort beim Laden: Ein leeres Pflichtfeld ist bereits ungültig, bevor der Nutzer überhaupt tippen konnte – das Formular „schreit“ ihn von Anfang an rot an. In der Praxis kombiniert man deshalb z. B. mit :placeholder-shown, :focus oder den neueren Pseudoklassen :user-invalid/:user-valid, die erst nach einer Interaktion greifen.

:enabled/:disabled – Zustand kommt aus HTML, nicht aus CSS

CSS kann den disabled-Zustand nur darstellen, nicht ändern. Ein echtes „Feld per Checkbox freischalten“ braucht JavaScript – die Pseudoklasse übernimmt dann ausschließlich die visuelle Rückmeldung.
